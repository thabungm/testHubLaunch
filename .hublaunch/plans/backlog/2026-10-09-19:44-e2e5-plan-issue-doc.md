# E2E5: add docs/e2e5-plan-issue.md

## Plan Summary

- **Key decision**: Write the file byte-exact with **no trailing newline** (31 bytes). The issue says "Nothing else", and the earlier from-issue E2E (issue #285, PR #288, file `docs/e2e-from-issue.md` on branch `issue-285`) was written the same way.
- **Most important file**: `docs/e2e5-plan-issue.md` (new; the `docs/` directory does not exist yet and must be created).
- **Priority/complexity**: Low priority, Simple complexity. One new file, no code, no README change, no tests to add.

## Problem Statement

GitHub issue #312 asks for a single documentation file, `docs/e2e5-plan-issue.md`, whose entire content is the line `Planned from an existing issue.`. The repository has no `docs/` directory today, so the file (and the directory) must be created. Nothing else in the repository may change.

### Planning Context

> **Note**: This section captures the key points settled during planning so the implementation is fully specified without any chat history.

**Key Requirements Discussed:**

- The file path is exactly `docs/e2e5-plan-issue.md`, relative to the repository root.
- The file content is exactly the 31-byte string `Planned from an existing issue.` — capital `P`, a trailing period, no leading or trailing whitespace, no trailing newline, no heading, no front matter.
- The issue text says "Nothing else": no README edit, no test script, no tsconfig change, no other file.
- The tracking/branch name is `issue-312` (the default for a plan started from `--issue 312`).

**Decisions Made:**

- **No trailing newline (chosen) vs POSIX trailing `\n`**: The issue is literal ("Nothing else"), and the precedent file from the previous from-issue E2E (`docs/e2e-from-issue.md` on branch `issue-285`, created for issue #285) has no trailing newline. Keeping the same convention makes byte-exact verification unambiguous: the file must be exactly 31 bytes.
- **Use `printf '%s'` rather than `echo`**: `echo` appends a newline; `printf '%s'` writes exactly the bytes given.
- **No README or other documentation change**: explicitly excluded by the issue text.

**Out of Scope:**

- Any change to `README.md`, `package.json`, `tsconfig.json`, `scripts/`, or `.hublaunch/` (other than the plan file HubLaunch itself commits).
- Adding tests, build steps, or lint rules for `docs/`.
- Any other file under `docs/`.

- **Why is this needed?** It is an end-to-end test (E2E5) of HubLaunch's `/hula-plan --issue <n>` flow: plan from an existing GitHub issue, launch under the `issue-<n>` tracking name, and open a PR that closes the issue. The file is the observable marker that the flow ran.
- **Current state**: `docs/` does not exist. `git ls-files docs` returns nothing.
- **Who is affected?** Only the HubLaunch E2E test run. No user-facing behaviour of the Contact Us scripts changes.

**Current Behavior**:

- Repository root contains `README.md`, `ralph.md`, `package.json`, `tsconfig.json`, `scripts/`, `.hublaunch/`, `.agents/`, `.github/`. No `docs/` directory.

**Desired Behavior**:

- `docs/e2e5-plan-issue.md` exists on the work branch and contains exactly `Planned from an existing issue.` (31 bytes, no newline).
- All other tracked files are unchanged.

## Proposed Solution

**High-level approach**: Create the directory and write the file with a single `printf` so the bytes are exact, then verify size and content with `wc -c` and `od -c`. No diagram needed: this is a single-file change.

### Key Components

1. **`docs/e2e5-plan-issue.md`** (new)
   - What: one-line Markdown file, content `Planned from an existing issue.`, 31 bytes, no trailing newline.
   - Why this approach: the issue specifies the content literally; `printf '%s'` is the simplest way to write exact bytes without a newline.

**Pattern References:**
